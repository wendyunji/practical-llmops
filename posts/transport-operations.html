전송망 운용에서
실제로 보는 것들

전송망 운용의 목적은 광신호를 보내는 데서 끝나지 않는다. 손실·노이즈·분산·FEC·보호절체·이중화 수준을 지속적으로 확인해 서비스가 끊기지 않도록 유지하는 일이다.

OperationsOpticalFECOTDRProtection

1. IP망과 전송망의 역할을 나눠 보기

IP망이 목적지와 Next-Hop을 판단하는 내비게이션이라면, 전송망은 실제 트래픽이 이동하는 물리적 고속도로에 가깝다. IP 경로가 논리적으로 정상이어도 광 회선이나 전송장비에 문제가 있으면 실제 서비스는 전달되지 않는다.

2. 장거리에서는 신호 품질이 핵심

광신호는 거리가 길어질수록 약해진다. 장거리 전송에서는 증폭, 오류 정정, 중계·재생과 예비 경로 설계가 함께 필요하다. FEC는 전송 과정에서 생긴 일부 오류를 수신 측에서 복원하기 위한 대표적인 기술이다.

항목운용 관점
Loss광선로와 접속점에서 발생하는 감쇠 확인
Noise신호 대비 잡음 증가 여부 확인
Dispersion장거리 전송에서 펄스가 퍼지는 현상 관리
FEC수신 오류 보정 수준과 품질 여유 확인
Protection주 경로 장애 시 예비 경로로 절체 가능한지 확인

3. WDM은 용량, 보호절체는 생존성

WDM/DWDM은 같은 광섬유에 여러 파장을 실어 전송 효율을 높인다. 반면 보호절체는 장비나 선로 장애가 발생했을 때 서비스를 계속 유지하기 위한 구조다. 운용에서는 단순히 회선 하나가 이중화돼 있는지만 보는 것이 아니라 카드, Shelf, 장비, 국사, 선로까지 어떤 수준에서 단일 장애점을 제거했는지 확인해야 한다.

4. OTN과 ASON

OTN은 광 전송 자원을 구조적으로 다루면서 오류 관리와 서비스 매핑을 가능하게 한다. ASON은 광 경로를 더 유연하게 설정하고 복구하는 개념으로 이해할 수 있다. 둘 다 결국 전송망의 생존성과 복구 유연성을 높이는 방향과 연결된다.

5. OTDR로 선로 장애 위치를 찾는다

OTDR은 광섬유에 시험 신호를 보내 반사되는 특성을 분석해 손실 지점과 단선 위치를 추정한다. 장애가 ‘장비 문제인지, 광선로 문제인지, 어느 거리에서 발생했는지’를 좁히는 데 유용하다.

Alarm 발생 → 장비 / Card / Port 상태 확인 → 광 Power / Error / FEC 상태 확인 → 보호절체 동작 여부 확인 → 선로 의심 시 OTDR → 손실/단선 지점 추정 → 현장 복구 및 사후 검증

6. 운용의 중심은 예방과 자동화로 이동한다

구축이 끝난 뒤의 전송망에서는 장애 예방, 안정적인 유지보수, 비용 효율화와 자동화가 중요하다. 장비가 많아질수록 모든 알람을 사람이 개별 확인하기보다, 장비·회선·선로 상태를 연결하고 장애 위험을 조기에 찾는 체계가 필요해진다.
