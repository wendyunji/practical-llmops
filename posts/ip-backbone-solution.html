IP BACKBONE · SOLUTION

IP백본망 솔루션

가입자 Internet/IPTV Traffic Flow를 출발점으로 OSI, DHCP/DNS, IPTV Multicast, Routing Protocol, MPLS까지 연결해서 본 노트.

1. 가입자 Internet / IPTV Traffic Flow

OSI 7 Layer와 SDU / PCI / PDU

통신 데이터는 상위 계층에서 하위 계층으로 내려가며 각 계층의 제어정보가 붙는다. 위 계층에서 내려온 순수 Data가 SDU(Service Data Unit), 현재 계층이 붙이는 Header/Trailer 같은 Control Information이 PCI(Protocol Control Information), SDU와 PCI가 합쳐진 현재 계층의 완성 Data Unit이 PDU다. 수신측에서는 반대 순서로 Header를 제거하면서 상위 계층으로 올린다.

상위 Layer Data = SDU
현재 Layer Control = PCI
SDU + PCI = PDU

송신: Upper → Lower, Encapsulation
수신: Lower → Upper, Decapsulation

Unicast / Broadcast / Multicast

방식의미대표 사용
Unicast1:1일반 Internet Session, VoD 등.
Broadcast1:N, 동일 Broadcast Domain 전체ARP, 초기 DHCP Discover 등.
Multicast1:특정 GroupIPTV 실시간 Channel.

IPTV는 동일 채널을 많은 가입자가 동시에 보기 때문에 Multicast가 효율적이다. 가입자가 채널을 선택하면 해당 Multicast Group에 Join하고, 채널을 바꾸거나 종료하면 Leave한다. 가입자측 Group Membership은 IGMP, L3 Multicast Tree 구성은 PIM과 연결된다.

2. FTTx / HFC / IP Backbone 망 구성

가입자 Access 종류는 달라도 상위로 올라가면 집선 계위를 거쳐 Backbone과 Service Network로 연결된다. Internet망과 IPTV망은 Traffic 특성과 운영 목적이 달라 별도 Service Plane으로 구성될 수 있으며, 주요 연동 구간은 이중화가 중요하다.

FTTx 가입자 → ONU/ONT → OLT ┐
                             ├→ AR / DS → Core / Service Network
HFC 가입자  → Cable Modem → CMTS ┘

서비스 관점에서 장비 이름을 외우기보다 ‘가입자를 수용하는 계위’, ‘지역 Traffic을 집선하는 계위’, ‘Core에서 외부/Service망으로 연결하는 계위’를 나눠 보는 것이 좋다.

3. DHCP와 DNS

DHCP

DHCP는 Client가 사용할 IP Address, Subnet Mask, Gateway, DNS 등의 Network Parameter를 자동 할당하는 Protocol이다. 기본 흐름은 DORA로 정리한다.

단계동작
DiscoverClient가 자신의 IP가 없기 때문에 Broadcast로 DHCP Server를 탐색.
OfferServer가 사용 가능한 IP와 설정값을 제안.
RequestClient가 여러 Offer 중 선택한 Server/IP를 요청.
ACKServer가 최종 Lease와 Parameter를 승인.
Client                    DHCP Server
  |---- Discover -------------->|
  |<--- Offer ------------------|
  |---- Request --------------->|
  |<--- ACK --------------------|

DHCP Relay가 필요한 이유

Discover는 Broadcast인데 Router는 Broadcast를 다른 L3 Network로 그대로 전달하지 않는다. 따라서 Access/집선 장비가 DHCP Relay Agent 역할을 하여 Client의 요청을 DHCP Server까지 Unicast 형태로 전달하고, Server 응답을 다시 가입자 Segment로 넘긴다.

Client Broadcast
→ Access / Relay Agent
→ L3 Network를 통해 DHCP Server
→ Relay Agent
→ Client

DNS

DNS는 사람이 사용하는 Domain Name을 통신 가능한 IP Address로 변환한다. Internet Service에서 DNS가 장애 나면 IP Reachability 자체는 살아 있어도 사용자는 대부분의 Service를 정상적으로 이용하기 어렵다. 따라서 DNS 역시 이중화와 공격/오동작 대응이 중요하다.

4. IPTV의 이해

IPTV는 Internet Protocol 기반 TV Service다. 실시간 방송은 같은 Stream을 많은 수신자가 공유하므로 Multicast가 핵심이고, VoD는 사용자별 요청이 다르므로 Unicast/CDN 방식이 중심이다.

Channel Join / Leave

STB에서 Channel 선택
→ IGMP Join
→ Access / L3 Multicast Network가 Group Membership 반영
→ PIM 기반 Multicast Tree에서 Stream 전달
→ Channel 변경
→ 기존 Group Leave + 새 Group Join

실시간 Channel에는 Multicast Group Address가 대응되고, Network는 실제 수신자가 있는 Branch 방향으로만 Stream을 복제해 전달하도록 설계한다.

IGMP / PIM / SSM

기술역할
IGMPHost/STB와 L3 Gateway 사이에서 Multicast Group 가입/해제 관리.
PIMRouter 사이의 Multicast Routing Tree 구성.
SSMSource-Specific Multicast. 특정 Source와 Group 조합을 기준으로 Stream 수신.

5. Routing Protocol의 이해

Routing Protocol은 목적지까지 어떤 Path로 Packet을 보낼지 판단하기 위해 Network 장비끼리 Reachability 정보를 교환하는 규약이다.

Static / Dynamic

Static Route는 운영자가 직접 Path를 지정하고, Dynamic Routing은 Protocol이 Network Topology 변화에 따라 Path를 학습·재계산한다.

분류핵심 관점
Distance Vector이웃으로부터 거리/방향 정보를 받아 최적 Path 계산.
Link StateTopology 상태를 공유하고 Cost 기반 최단 경로 계산.
Path Vector경로 자체의 AS Path/정책 정보를 이용. 대표적으로 BGP.

실제 Backbone에서는 IGP(OSPF/IS-IS)가 내부 Next-Hop Reachability를 보장하고, BGP가 외부/서비스 Prefix 정책과 Path를 전달하는 식으로 역할을 나눈다.

6. MPLS의 이해

MPLS는 Multi Protocol Label Switching의 약자로, Packet에 Label을 붙이고 Label 기준으로 전달하는 기술이다. IP Prefix Lookup을 매 Hop마다 수행하는 관점보다, 미리 만들어진 Label Switched Path를 따라 Traffic을 전달하고 VPN/Traffic Engineering 같은 Service를 구성하는 데 의미가 크다.

용어역할
LERLabel Edge Router. MPLS Domain 경계에서 Label Push/Pop.
LSRLabel Switch Router. 내부에서 Label Swap.
LSPLabel Switched Path. Label Traffic이 따라가는 논리 경로.
LDPLabel Distribution Protocol. Label 정보를 이웃 Router와 교환.
Ingress LER
→ Label Push
→ LSR: Label Swap
→ LSR: Label Swap
→ Egress LER: Label Pop
→ IP Forwarding
