인터넷과 IP망을
한 장으로 이해하기

인터넷은 하나의 중앙망이 아니라 서로 다른 정책을 가진 네트워크들의 연결이다. 이 글은 AS와 BGP에서 시작해 내부 라우팅, RIB/FIB, 트래픽 관측과 DDoS 대응까지 IP망의 큰 그림을 연결한다.

1. 인터넷은 ‘네트워크들의 네트워크’다

인터넷은 한 회사가 운영하는 단일망이 아니라 ISP, CDN, CP, IX, Transit Provider 등 서로 다른 네트워크가 각자의 정책으로 연결된 구조다. 각 정책 단위를 AS(Autonomous System)라고 하고, 서로 다른 AS가 인터넷 경로를 교환할 때 핵심적으로 사용하는 프로토콜이 BGP다.

구성요소역할
ISP가입자에게 인터넷 접속을 제공하는 사업자
CDN / CP콘텐츠를 제공하거나 사용자 가까이에 캐싱
IX여러 사업자가 직접 트래픽을 교환하는 지점
Transit Provider다른 사업자의 트래픽을 더 넓은 인터넷으로 전달

AS는 장비 한 대가 아니라 하나의 라우팅 정책 단위로 보는 편이 이해하기 쉽다.

2. BGP가 목적지를 알려주고 IGP가 내부 도달성을 만든다

BGP는 “이 Prefix는 이 AS 경로를 통해 갈 수 있다”는 정보를 교환한다. 하지만 BGP가 알려준 Next-Hop까지 실제로 도달하려면 사업자 내부의 OSPF나 IS-IS 같은 IGP가 내부 경로를 제공해야 한다. 같은 AS 내부에서 BGP 경로를 전달할 때는 iBGP, 다른 AS와 경로를 교환할 때는 eBGP를 사용한다.

외부 Prefix 광고 → eBGP → 내부로 경로 전달(iBGP) → OSPF / IS-IS가 Next-Hop 도달성 보장 → 라우터가 Best Path 선정 → FIB 기반 고속 포워딩
프로토콜주요 역할
OSPF내부망의 IP 도달성 제공
IS-IS대형 백본 내부의 도달성 제공
iBGP같은 AS 내부에서 BGP 경로 전달
eBGP서로 다른 AS 사이에서 인터넷 경로 교환
IGMP / PIMMulticast 수신자 관리와 L3 경로 구성

3. 경로를 ‘배우는 것’과 패킷을 ‘보내는 것’은 다르다

라우팅 프로토콜이 학습한 경로는 라우팅 정보베이스에 모이고, 실제 패킷 처리에는 포워딩에 최적화된 FIB가 사용된다. 목적지 IP와 가장 구체적으로 일치하는 Prefix를 고르는 Longest Prefix Match가 핵심이며, 여러 후보가 있으면 프로토콜 우선순위와 Metric 같은 조건을 함께 본다.

Destination IP → Longest Prefix Match → 선택된 Route / Next-Hop → FIB Lookup → Output Interface → Packet Forwarding

인터넷에서는 가는 길과 오는 길이 반드시 같지 않다. BGP 정책과 피어링 구조 때문에 비대칭 경로가 흔하고, 장애 분석 시 왕복 경로를 따로 봐야 하는 이유도 여기에 있다.

4. 트래픽은 Flow와 SNMP로 서로 다른 관점에서 본다

5 Tuple 기반 Flow는 누가 누구와 어떤 프로토콜·포트로 통신하는지 흐름을 본다. SNMP는 인터페이스 트래픽, 오류, 자원 상태 같은 장비 중심 지표에 강하다. 둘을 함께 보면 ‘인터페이스 사용량이 늘었다’와 ‘어떤 트래픽이 증가했는가’를 연결할 수 있다.

  • Flow: Source/Destination IP, Port, Protocol 기반 트래픽 분석
  • SNMP: 인터페이스 사용량, 에러, CPU/메모리 등 장비 상태
  • Traceroute: 실제 홉 경로와 지연 위치를 확인

5. 라우팅 보안과 장애 분석

DDoS 대응에는 Blackhole, Sinkhole, Clean Zone 같은 방식이 쓰이고, 잘못된 BGP Prefix 광고를 줄이기 위해 IRR, RPKI, ROA, ROV 같은 검증 체계가 사용된다.

장애 분석 체크 순서
라우팅 테이블에 경로가 있는가 → Default Route가 필요한가 → Next-Hop이 유효한가 → 왕복 경로가 비대칭인가 → BGP 광고가 정상인가 → 특정 Peer/IX/Transit 문제인가 → Flow와 SNMP가 같은 현상을 가리키는가 → 필터링이나 Blackhole 정책이 걸렸는가.
