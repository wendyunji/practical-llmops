1. Internet이란 무엇인가

Internet은 한 기관이 관리하는 하나의 Network가 아니라 수많은 ISP, Cloud, CDN, CP, Enterprise Network가 서로 연결된 Network of Networks다. 각 Network는 자신의 Routing Policy를 가지고 있고, 중앙 통제자 없이 상호 연결 관계와 Protocol로 전체 Internet이 구성된다. 오늘날 Traffic은 TCP뿐 아니라 Streaming, QUIC, Gaming, Voice 등 UDP 기반 비중도 크다.

2. AS와 BGP

AS(Autonomous System)는 하나의 Routing Policy를 공유하는 Network 단위다. ASN은 AS의 식별번호이고, BGP(Border Gateway Protocol)는 AS 사이에서 어떤 Prefix에 도달할 수 있는지를 광고한다.

AS A: “203.0.113.0/24는 나를 통해 갈 수 있다.”
AS B: “그 Prefix에 가려면 AS A 방향으로 보낸다.”

3. Internet 구성 요소

요소역할
ISP가입자에게 Internet Access 제공.
CP콘텐츠/서비스 원본 제공.
CDN콘텐츠를 사용자 가까이 Cache.
IX여러 AS가 Traffic을 교환하는 공용 접점.
Transit다른 Network에 더 넓은 Internet Reachability를 유료 제공.
Peering두 Network가 상호 Traffic을 직접 교환.
User → Access → Aggregation → Core → GI / IX / CDN / IDC / Peer / Transit → Destination

4. TTL과 Hop

TTL(Time To Live)은 Packet이 Routing Loop에서 무한히 떠돌지 않게 하는 값이다. Router 한 Hop을 통과할 때마다 1씩 감소하고 0이 되면 Packet이 폐기된다. Traceroute는 이 동작을 이용해 Hop을 하나씩 드러낸다.

5. Router의 기본 동작

Router는 Destination IP를 보고 Routing/Forwarding Table에서 가장 적합한 Next-Hop과 Output Interface를 선택한다. 기본적으로 Source IP보다 Destination IP가 Forwarding 판단의 중심이다.

Packet 도착
→ Destination IP 확인
→ FIB Lookup
→ Longest Prefix Match
→ Next-Hop / Output Interface
→ L2 Header 재작성
→ Forward

6. Default Route

더 구체적인 Route가 없을 때 사용하는 최후의 경로다. IPv4에서는 0.0.0.0/0로 표현한다. Access/Enterprise 구간은 전체 Internet Route를 보유하지 않고 Default Route로 상위 Gateway에 보내는 경우가 흔하다.

7. Static Routing과 Dynamic Routing

방식특징
Static운영자가 직접 Prefix와 Next-Hop을 지정. 단순하지만 Topology 변화 자동 반영 어려움.
DynamicOSPF, IS-IS, BGP 같은 Protocol이 Route를 학습하고 변화에 따라 갱신.

8. Unicast / Broadcast / Multicast

방식범위예
Unicast1:1Web, API, 일반 Session.
Broadcast동일 Broadcast Domain 전체ARP Request, DHCP Discover.
Multicast특정 GroupIPTV Live Stream.

9. 5 Tuple과 Flow

Flow는 개별 Packet 한 개가 아니라 일정 시간 동안 동일한 통신 특성을 가진 Packet 묶음이다. 대표 식별자는 Source IP, Destination IP, Source Port, Destination Port, Protocol의 5 Tuple이다.

10. Flow Sampling / Export

Backbone Traffic은 모든 Packet을 전부 저장하기 어려우므로 일부 Packet을 Sampling해 통계적으로 Flow를 추정하고 Collector로 Export한다. DDoS 탐지, Traffic Engineering, 고객별 사용량, Capacity Planning에 활용한다.

11. IDS, IPS, Clean Zone

기술역할
IDS이상·침입 Traffic 탐지.
IPS탐지 후 Inline 차단까지 수행.
Clean Zone의심 Traffic을 Scrubbing Center로 우회해 정상 Traffic만 복귀.

12. IP Header와 Fragmentation

IPv4 Header에는 Source/Destination, TTL, Protocol, Identification, Fragment Offset 등의 정보가 있다. Path MTU보다 큰 Packet이 Fragment될 경우 첫 Fragment 이후 조각에는 Transport Header 정보가 없을 수 있어 Flow/Security 분석이 복잡해진다.

13. Blackhole, Sinkhole, Clean Zone

방법목적
Blackhole공격 Traffic을 Null로 버려 Network 전체를 보호. 대상 Service도 함께 차단될 수 있음.
Sinkhole의심 Traffic을 분석용 환경으로 유도.
Clean Zone공격 Traffic을 정화하고 정상 Traffic은 Service로 전달.

14. IPv4 주소체계

IPv4는 32bit 주소다. 초기 Class A/B/C 방식은 주소 공간을 큰 고정 단위로 배정해 낭비가 컸고, 이후 CIDR가 도입되어 Prefix Length로 유연하게 주소 공간을 나누게 됐다.

15. CIDR

CIDR(Classless Inter-Domain Routing)은 /24, /20, /32처럼 Prefix Length로 Network 범위를 표현한다. Prefix가 길수록 더 구체적인 작은 주소 범위를 의미한다.

16. Subnetting과 Supernetting

Subnetting은 큰 Prefix를 작은 Prefix로 나누고, Supernetting/Aggregation은 여러 연속 Prefix를 상위 Summary Prefix로 묶는다. Aggregation은 Routing Table 크기와 Update 규모를 줄이는 데 중요하다.

17. Routing Table(RIB)과 Forwarding Table(FIB)

RIB에는 Static, OSPF, IS-IS, BGP 등 여러 Source에서 학습한 Route 후보와 선택 결과가 저장된다. 실제 Data Plane은 선택된 Route를 Forwarding에 최적화한 FIB를 사용한다.

Routing Protocol → RIB → Best Route → FIB → Hardware Forwarding

18. DHCP

DHCP는 Client가 IP, Gateway, DNS 등을 자동으로 받게 한다. Discover → Offer → Request → ACK의 DORA 절차가 기본이며, Broadcast가 L3 경계를 넘지 못하므로 다른 Subnet의 DHCP Server를 사용할 때 Relay Agent가 필요하다.

19. TCP와 Window

TCP는 Reliable Delivery를 위해 Sequence, ACK, Retransmission, Window를 사용한다. RTT가 긴 환경에서 한 Packet씩 ACK를 기다리면 효율이 낮기 때문에 Sliding Window로 여러 Segment를 동시에 전송한다.

20. ICMP와 Traceroute

ICMP는 IP 통신의 제어/오류 메시지에 사용된다. Ping은 Echo Request/Reply, Traceroute는 TTL을 단계적으로 증가시켜 중간 Router의 Time Exceeded 응답을 이용해 Path를 추정한다. 일부 Hop이 응답하지 않아도 최종 목적지까지 도달한다면 실제 Forwarding Path는 살아 있을 수 있다.

21. ARP와 L2 Switching

같은 L2 Segment에서 IP Packet을 보내려면 다음 Hop의 MAC Address를 알아야 한다. ARP가 IP→MAC Mapping을 해결하고 Switch는 Source MAC을 학습해 MAC Table을 만든다. Unknown Destination은 Flooding되고 이후 학습된 Port로만 Forward된다.

22. Multicast, IGMP, PIM

Host/STB는 IGMP로 Group Join/Leave를 알리고, Switch는 IGMP Snooping으로 어느 Port에 Receiver가 있는지 추적한다. Router는 PIM으로 L3 Multicast Tree를 구성해 필요한 Branch에서만 Stream을 복제한다.

23. MPLS

MPLS는 Packet에 Label을 붙여 MPLS Domain 내부에서 Label 기반으로 전달한다. Edge에서는 Push/Pop, Core LSR에서는 Swap을 수행한다. VPN, Traffic Engineering, Service Separation에 널리 활용된다.

24. Route 선택 원리

서로 다른 개념을 순서대로 구분해야 한다.

  1. Longest Prefix Match: Destination에 가장 구체적인 Prefix 선택.
  2. Route Source / Administrative Distance: 동일 Prefix를 여러 Protocol에서 배웠을 때 어떤 Source를 신뢰할지 결정.
  3. Metric / Protocol Best Path: 동일 Protocol 내 후보 중 더 좋은 경로 결정.
  4. Recursive Lookup: 선택된 Next-Hop이 실제 어느 Interface로 나가는지 다시 해석.

25. In Policy와 Out Policy

BGP는 단순 최단거리 Protocol이 아니라 정책 기반 Routing이다. In Policy는 상대가 광고한 Route를 수신할 때 Filter/Preference를 적용하고, Out Policy는 우리 Prefix 중 무엇을 상대에게 어떤 Attribute로 광고할지 결정한다.

26. OSPF

OSPF는 Link-State IGP다. Router들이 Link State를 공유하고 SPF Algorithm으로 최단 Path를 계산한다. 대형 Network에서는 Service Prefix를 모두 IGP에 넣기보다 Loopback/Trunk 등 Infrastructure Reachability 중심으로 유지해 Stability를 높인다.

27. IS-IS

IS-IS 역시 Link-State IGP이며 대형 ISP Backbone에서 많이 사용된다. Level-1은 Area 내부, Level-2는 Area 간 Backbone 역할로 이해할 수 있다.

28. BGP

BGP는 Path-Vector 기반의 Policy Routing Protocol이다. AS_PATH, NEXT_HOP, LOCAL_PREF, MED, Community 등 다양한 Attribute를 활용해 단순 Shortest Path가 아닌 Business/Traffic Policy에 맞춰 Best Path를 결정한다.

29. Loopback과 Next-Hop

Loopback은 물리 Port와 독립적인 논리 Interface라 Router가 살아 있는 동안 안정적으로 유지된다. BGP Session, Router ID, Management Endpoint에 자주 사용된다. BGP가 알려준 Next-Hop까지 실제로 도달하려면 IGP가 그 Loopback/Transit 경로를 알고 있어야 한다.

30. Backbone 설계 맥락

대형망에서는 Protocol별 역할을 분리하는 것이 중요하다. BGP는 서비스/외부 Prefix와 Policy를 운반하고, OSPF/IS-IS는 Router Loopback과 Trunk Reachability, ECMP 등 내부 전달 기반을 제공하는 식이다.

BGP Route: “목적지는 10.10.10.1 Next-Hop 방향”
IGP: “10.10.10.1까지는 이 Trunk/ECMP Path로 도달”
FIB: 실제 Packet Forward

31. 예상치 못한 경로 문제가 생기는 이유

모든 Router가 Full Internet Table을 가지는 것은 아니다. 계층 설계에서 예상하지 못한 Direction으로 Packet이 들어오면 해당 Router에 상세 Route나 Default Route가 없어 Drop/Loop가 발생할 수 있다. Summary와 Default, Policy Scope가 중요한 이유다.

32. iBGP Full Mesh 문제

기본 iBGP에서는 iBGP로 배운 Route를 다른 iBGP Peer에게 다시 광고하지 않는다. Loop Prevention을 위한 규칙이지만 Router 수가 늘면 모든 Router가 서로 Session을 맺어야 하는 Full Mesh 부담이 커진다.

N Router Full Mesh Session 수 ≈ N(N-1)/2

33. Route Reflector

RR(Route Reflector)는 iBGP Full Mesh 문제를 줄인다. Client는 모든 Router와 Session을 맺는 대신 RR과 연결하고, RR이 iBGP Route를 다른 Client에게 Reflect한다.

34. AS Confederation

큰 AS를 내부적으로 여러 Sub-AS처럼 나눠 운영하되 외부에는 하나의 AS로 보이게 하는 방식이다. 대형 Network의 BGP 확장성과 관리 Domain 분리를 위해 사용할 수 있다.

35. eBGP와 iBGP

동일 Prefix 후보에서 외부 AS와 직접 연결된 eBGP Route가 iBGP보다 우선되는 상황이 일반적이다. 이는 Vendor의 AD 기본값과 BGP Best Path Rule 모두와 연관된다. 정확한 선택 순서는 장비/정책에 따라 확인해야 한다.

36. Transit과 Peering

관계의미
Transit상대에게 비용을 지불하고 넓은 Internet Reachability를 구매.
Peering두 Network가 서로의 고객 Traffic을 직접 교환. Settlement 방식은 계약에 따라 다름.

37. Public Peering과 Private Peering

Public Peering은 IX의 Shared Fabric에서 여러 사업자가 연결되는 방식이고, Private Peering은 두 사업자가 전용 Link를 직접 구성한다. Traffic 규모, 품질, 비용, 운영 복잡도에 따라 선택한다.

38. Route Server와 Selective Peering

IX Route Server는 참가자가 모든 사업자와 개별 BGP Session을 맺지 않아도 Route를 교환할 수 있게 한다. Community와 Policy를 활용해 특정 참가자에게만 광고하거나 일부 Route를 제외하는 Selective Peering을 구성할 수 있다.

39. Internet Direct 서비스 범위와 Routing

Internet Direct는 고객에게 어느 범위의 Route를 제공하느냐에 따라 Domestic, International, Default Route 포함 여부 등이 달라질 수 있다. Route Community와 Import/Export Policy를 이용해 Service Scope를 구분한다. 구체 Community 값은 내부 정책에 의존하므로 실제 운영 시 기준 문서를 확인한다.

40. Routing Security

BGP는 상대가 광고하는 Prefix 정보에 기반하므로 잘못된 Route Advertisement나 Hijack에 취약할 수 있다. 이를 줄이기 위해 IRR Filter, Prefix/AS-Path Filter, Max-Prefix, RPKI 기반 ROA/ROV 등을 사용한다.

기술역할
IRR등록된 Routing Object를 기반으로 Filter 생성에 활용.
RPKI암호학적으로 Prefix와 Origin AS 권한 관계 검증.
ROA어떤 AS가 어떤 Prefix를 Origin할 수 있는지 선언.
ROV수신 BGP Route의 Origin Validation 수행.
