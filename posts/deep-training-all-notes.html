NETWORK · CONSOLIDATED NOTE

심화교육 전체 노트 정리

IP망을 한 문장으로

패킷이 목적지까지 가는 경로를 정하고, 실제로 전달하고, 문제가 생겼을 때 관측·차단·우회하는 체계.

BGP가 목적지 Prefix를 알려준다.
OSPF / IS-IS가 BGP Next-Hop까지의 내부 경로를 보장한다.
라우터는 Route 정보와 LPM, AD, Metric을 이용해 경로를 선택한다.
실제 Packet Forwarding은 FIB 기준으로 빠르게 수행된다.
Flow / SNMP / Traceroute로 장애와 공격을 관측한다.
Blackhole / Clean Zone / RPKI 같은 정책으로 망을 보호한다.

1. 인터넷의 기본 구조

인터넷은 하나의 중앙 사업자가 통제하는 단일망이 아니라 수많은 자율 네트워크가 서로 연결된 Network of Networks다. 각 사업자, CDN, CP, IX, Transit 사업자가 각자의 Routing Policy를 가지고 BGP로 경로 정보를 교환한다.

주체역할
ISP가입자에게 Internet Access 제공.
CDN콘텐츠를 사용자 가까이에 Cache.
CP콘텐츠/서비스 제공.
IX여러 Network가 Traffic을 직접 교환하는 지점.
Transit다른 AS의 Traffic을 더 넓은 Internet으로 전달.

2. AS와 BGP

AS(Autonomous System)는 하나의 자율 Routing Policy를 가진 Network 단위다. ASN은 이 AS를 식별하는 번호이며, BGP는 AS 간 Reachability와 Path 정보를 교환한다.

“이 Prefix는 우리 AS를 통해 갈 수 있다.”
“이 목적지까지는 이 AS Path를 거친다.”

3. Packet 전달 기본

Router는 목적지 IP를 기준으로 Routing Table을 조회하고 가장 구체적인 Prefix를 우선 선택한다. BGP Next-Hop 자체가 다시 다른 Route로 해석되어야 하면 Recursive Lookup이 필요하다.

Route Selection에서 자주 보는 항목

항목의미
Longest Prefix Match가장 구체적으로 일치하는 Prefix를 우선.
Administrative Distance서로 다른 Routing Source의 신뢰도 비교.
Metric같은 Protocol 안에서 Path Cost 비교.
Recursive LookupNext-Hop에 도달하기 위한 Route를 다시 조회.

4. Routing Protocol 역할

Protocol역할
OSPFInternal IP Reachability.
IS-IS대형 Backbone의 Internal Reachability.
iBGP동일 AS 내부에서 BGP Route 전달.
eBGP다른 AS와 Internet Route 교환.
PIMMulticast L3 Path 구성.
IGMPMulticast Receiver Join/Leave 관리.

5. Addressing과 Prefix

IPv4는 Classful 주소 체계에서 CIDR 기반 Prefix 체계로 발전했다. Subnetting은 큰 주소 공간을 더 작은 Network로 나누는 것이고, Supernetting/Aggregation은 여러 Prefix를 묶어 Routing Table 규모를 줄이는 방향이다.

6. Traffic Observation

Packet 하나하나를 모두 저장하기 어렵기 때문에 Network에서는 Flow 단위 분석이 중요하다. Source/Destination IP, Port, Protocol 같은 5-Tuple을 기준으로 Traffic 흐름을 집계하면 장애 분석, Capacity Planning, DDoS 탐지에 활용할 수 있다.

도구/데이터관점
SNMPInterface Counter, Traffic Volume, Error 등 장비 지표.
Flow누가 누구에게 얼마나 Traffic을 보냈는지.
TraceroutePath/Hop 관점의 Reachability 확인.
Syslog / Alarm장비 Event와 상태 변화.

7. Security와 Routing Policy

DDoS나 잘못된 Route 광고는 단순 장애와 다른 방식으로 Network를 흔든다. Blackhole, Sinkhole, Clean Zone 같은 Traffic Control 기법과 IRR/RPKI/ROA/ROV 같은 Route Validation 체계를 함께 이해해야 한다.

장애 분석 체크리스트

Routing Table에 목적지 Route가 있는가?
Default Route가 있는가?
Next-Hop이 Reachable한가?
Outbound와 Return Path가 다른가?
BGP Advertisement가 정상인가?
특정 IX / Transit / Peer 구간 문제인가?
SNMP Traffic과 Flow Traffic이 일치하는가?
Blackhole / Filter / Policy가 적용되어 있는가?

8. 전체 맥락

Backbone Network를 이해할 때 Protocol 이름을 따로 외우기보다 ‘경로를 배운다 → 내부적으로 Next-Hop까지 도달한다 → Packet을 Forwarding한다 → Traffic을 관측한다 → 장애/공격을 Policy로 제어한다’는 하나의 흐름으로 보는 것이 이해에 도움이 된다.
