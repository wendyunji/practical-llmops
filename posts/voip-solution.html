VOICE · VOIP · ENGINEERING

VoIP망 솔루션 / Engineering

방향

기존 PSTN은 점진적으로 VoIP로 Migration되고 있고, 전체 방향은 All-IP다. 다만 전화 서비스가 요구하는 전원, 긴급통화, 품질, 번호·지역 정책, 보안과 고가용성을 IP망 위에서 다시 구현해야 한다.

1. PSTN에서 VoIP로

기존 전화망은 가입자망, 전달망, 시내전화망, 국제전화망, 지능망 등 여러 계층으로 구성됐다. 현재는 VoIP가 확대되면서 기존 교환기와 IP 기반 전화망이 함께 존재하는 Hybrid 단계로 볼 수 있다.

PSTN 중심
→ PSTN + VoIP Hybrid
→ SoftSwitch / IMS
→ All-IP Voice Network

국제전화와 기업 전화 등 많은 영역에서도 IP 기반 전달 비중이 커졌고, 가입자 단말이 기존 Analog 방식이어도 중간 Gateway를 통해 내부적으로 IP망에 수용될 수 있다.

2. 전화망 계위와 가입자 수용

고객 입장에서는 벽단자와 전화기만 보이지만 뒤에는 가입자 수용 설비와 상위 전달/교환망이 있다. 기존 가입자망은 COT, RT 등 여러 Access 설비로 구성될 수 있고, IP 전환 이후에는 AGW/MTA/IP Phone 같은 장비가 Legacy 단말과 IP Voice Core 사이를 연결한다.

Legacy Phone
→ Access / AGW / MTA
→ IP Transport
→ SoftSwitch / IMS
→ 상대망

3. 왜 E1을 IP로 바꾸는가

Legacy E1 기반 음성 회선은 고정 Channel 구조를 갖는다. 일반적인 E1은 2.048Mbps Frame에서 Signaling/Sync 등을 제외하면 약 30개의 64kbps Voice Channel을 수용하는 형태로 많이 사용됐다. Packet 기반으로 바꾸면 Traffic과 자원을 훨씬 유연하게 집선할 수 있다.

Legacy 회선 기반IP 기반
고정 Timeslot / Port 자원Packet/Server 자원을 유연하게 공유
서비스별 전용 설비 비중 큼하나의 IP Infrastructure에서 여러 Service 수용
증설 시 Hardware/회선 단위 확장Server/Capacity 중심 확장 가능
노후 교환기·상면·전력 부담집약화와 Software 기반 기능 확장

4. PSTN vs VoIP

관점PSTNVoIP

지역성시내통화권·지역번호와 물리 위치 관계가 강함IP 접속 특성상 거리 제약이 작음

PSTN의 전원 특성

전통 전화망은 국사/가입자망에서 급전되는 구조와 비상전원 체계 덕분에 가정 전원이 끊겨도 일반 전화가 동작할 수 있다는 강점이 있었다. IP 전화에서는 CPE와 Broadband Gateway가 꺼지면 통화가 어려워지므로 UPS, 핵심 설비 이중화와 재난 통신 설계가 별도로 중요하다.

5. 긴급통화와 Location Routing

인터넷전화에서 119 같은 긴급통화는 단순 Number Routing 문제가 아니다. 물리 위치와 IP 접속 위치가 분리될 수 있으므로 가입자 주소 정보를 기반으로 관할 기관을 결정해야 한다.

119 발신
→ 가입자 / 전화번호 확인
→ 등록 주소·회선·단말 정보 조회
→ Location Server
→ 지역 Code / 관할 기관 결정
→ Interworking Network
→ 가까운 긴급기관으로 착신

초기 Internet Phone에서 어려웠던 부분 중 하나가 위치 식별이었고, Service가 제도권 통신으로 자리잡으면서 Emergency Call, Number Portability, Quality Requirement 같은 체계가 함께 보완됐다.

6. QoS — 음성과 Data를 같이 보내되 똑같이 취급하지 않는다

Broadband 한 회선에는 Voice, IPTV, 일반 Internet Traffic이 동시에 존재할 수 있다.

Home Gateway
├─ SIP / RTP : Voice
├─ IPTV       : Video
└─ Internet   : Web / Download / Game

파일 다운로드는 조금 늦어도 재전송할 수 있지만 Voice는 실시간 대화라 Delay와 Jitter가 누적되면 바로 품질 저하로 느껴진다.

품질 요소영향
Delay왕복 대화가 늦어져 말이 겹침.
JitterPacket 도착 간격이 흔들려 Voice Playback이 불안정.
Packet Loss일부 음성이 누락·왜곡.
CongestionQueueing Delay와 Loss 증가.

따라서 Voice Traffic을 Classification하고 Priority Queue, Bandwidth Guarantee, Policing/Shaping 등 QoS 정책으로 보호하는 것이 중요하다.

7. All-IP가 해결하는 Legacy 문제

노후 PSTN 설비는 상면, 전력, 유지보수 인력, Spare Part, 개발 확장성에 한계가 생긴다. IP 기반으로 집약하면 같은 공간에서 더 많은 가입자와 Service를 수용하고 Software Upgrade로 기능 확장이 가능해진다.

  • 상면 절감
  • 전력 효율 개선
  • 가입자 수용 집적도 향상
  • Legacy Vendor / Spare 의존 감소
  • 기능 개발과 Service 연동 유연성
  • 전송망·데이터망과 Infrastructure 통합
다만 All-IP = 자동으로 더 안정적이라는 뜻은 아니다.

전화 서비스는 높은 가용성이 요구되므로 Server Cluster, Site 이원화, Network Path 이중화, DB Replication, DNS/SBC/Gateway 이중화를 함께 설계해야 한다.

8. 국사·System 이중화

Voice Core는 한 Site 장애가 전국 Call에 영향을 주지 않도록 지리적으로 분리된 Site와 Capacity를 갖춰야 한다. Application만 이중화하고 Access/Transport Path가 같은 Risk Segment를 공유하면 실제 재해 상황에서 의미가 줄어든다.

Site A Voice Core ─┐
                   ├→ Subscriber / Interconnect
Site B Voice Core ─┘

Control / DB / SBC / Gateway / Transport Path
각 계층의 Failure Domain을 따로 확인

9. Security

VoIP는 일반 IP Security Threat를 그대로 받으면서 전화망 특유의 과금·번호·Session Risk도 함께 가진다.

  • SIP Flood / DDoS
  • Registration Credential 탈취
  • Unauthorized Call / Toll Fraud
  • RTP 도청 위험
  • 잘못된 Routing / Number Spoofing
  • 관리 Interface와 CPE 취약점

SBC, Firewall, ACL, Rate Limit, 인증서·암호화, Session Monitoring을 함께 적용하고, 관리망과 Service망 접근 통제를 분리하는 것이 중요하다.

10. VoIP Migration을 보는 관점

PSTN을 VoIP로 바꾼다는 것은 Protocol을 SIP로 교체하는 작업만이 아니다. 기존 PSTN이 오랫동안 제공해온 정전 대응, 긴급통화, 번호 정책, 통화 품질, 재난 대응, 높은 가용성을 IP 기반 구조로 다시 구현하면서 동시에 IP의 효율성과 확장성을 얻는 Migration이다.
