VOICE · PSTN

PSTN망 솔루션 / Engineering

PSTN은 단순한 ‘옛날 전화망’이 아니라, 통화 경로·신호·과금·상호접속·지능망의 기본 구조가 모여 있는 통신 서비스의 출발점이다.

핵심 흐름

가입자가 번호를 누르면 교환망이 번호를 분석하고 경로를 설정한다. 실제 음성은 회선으로 전달되고, 통화 설정·해제·과금 같은 제어는 별도 신호 체계가 담당한다. 통화가 다른 사업자망을 지나면 상호접속 정산이 발생하고, CDR은 과금과 이력의 근거가 된다.

1. PSTN의 기본 개념

PSTN(Public Switched Telephone Network)은 전통적인 일반 전화망이다. 가입자가 전화를 걸면 교환기가 발신자와 수신자 사이의 통화 경로를 설정하고, 통화 종료 후에는 통화 상세 기록을 남겨 과금과 정산에 사용한다.

2. 전화망 계위

구성역할
C5 교환기가입자와 직접 연결되는 하위 계위 교환기.
C4 교환기여러 하위 교환기를 상위에서 집선.
Tandem교환기 간 중계 역할.
SSP지능망 서비스와 연동 가능한 Service Switching Point 기능.
SCP지능망 서비스의 제어 로직을 수행.

전화망에서는 번호만 보고 상대방에게 곧장 가는 것이 아니라, 발신 위치·착신 번호·통화권·상위 교환기·사업자 간 경로를 단계적으로 판단한다.

3. 회선 교환

PSTN의 기본은 Circuit Switching이다. 통화가 시작되면 일정한 회선 자원을 잡고 통화가 끝날 때까지 유지한다. 품질 예측은 쉽지만, 트래픽이 없을 때도 자원을 유연하게 다른 서비스로 전환하기 어렵다.

Caller
  ↓
Local Exchange
  ↓
Tandem / Toll
  ↓
Remote Local Exchange
  ↓
Callee

4. CDR과 과금

CDR(Call Detail Record)은 통화 상세 기록이다. 발신번호, 수신번호, 시작/종료 시각, 통화 시간, 통화 경로 등이 포함될 수 있고 요금 계산·정산·장애 분석·이력 조회의 근거가 된다.

항목활용
발신/수신 번호통화 유형과 과금 대상 식별.
시작/종료 시각통화 시간과 시간대 정책 계산.
경로/교환 정보사업자 간 정산과 장애 분석.
결과 코드정상/실패 통화 상태 분석.

5. 상호접속료

자사 가입자가 타사 가입자에게 통화하면 상대 통신사의 망을 일부 사용한다. 이때 사업자 간 망 사용에 대한 정산이 필요하며 이를 상호접속료 관점으로 이해할 수 있다.

따라서 전화 서비스는 기술뿐 아니라 ‘누가 어느 구간의 망을 사용했는지’가 비용 구조와 직접 연결된다.

6. 전화 서비스 종류

서비스설명
PSTN 일반전화지역번호 기반 전통 유선전화.
디지털전화IP 기반 인프라를 활용하되 사용자에게는 기존 전화 형태로 제공 가능.

국제전화국가 간 통화 서비스.
로밍해외망을 사용하면서 기존 가입자 정보를 홈 사업자와 연동.

7. DID / DOD

기업 전화에서는 대표번호와 내선, 착발신 제어가 중요하다.

용어의미
DIDDirect Inward Dialing. 외부에서 기업 내부 번호로 직접 착신.
DODDirect Outward Dialing. 기업 내부에서 외부로 직접 발신.

9. SS7과 ISUP

PSTN에서는 실제 음성과 통화 제어를 분리해서 생각하는 것이 중요하다. 음성은 TDM 회선에 실리고, 통화 설정·응답·해제 같은 제어는 SS7 신호망을 통해 교환기 사이에 전달된다.

Voice Path : TDM / Circuit
Signaling  : SS7 → ISUP messages

즉, 전화가 연결되는 과정은 ‘목소리를 보내는 것’보다 먼저 수많은 제어 메시지 교환이 이루어지는 절차다.

10. 지능망과의 연결

PSTN 기본 교환 기능 위에 번호 번역, 대표번호, 착신과금, 부가서비스 로직을 추가한 것이 지능망이다. 교환기는 서비스 Trigger를 감지하고, 별도의 서비스 로직이 최종 연결 번호나 과금 정책을 결정할 수 있다.

11. PSTN에서 All-IP로

PSTN은 안정성이 높지만 노후 전용 장비, 상면, 전력, 유지보수 인력, 확장성 측면에서 한계가 있다. 그래서 통화 제어는 SoftSwitch/IMS로, 미디어는 RTP 기반 IP 전달로 점차 이동한다.

이 전환을 이해하려면 PSTN을 버려진 기술로 보는 것보다, 현재 IP 전화망이 어떤 기능을 소프트웨어와 패킷으로 다시 구현했는지 비교하는 기준점으로 보는 것이 도움이 된다.
