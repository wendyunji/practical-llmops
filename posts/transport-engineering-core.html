전송망 Engineering — 기간망

전송망의 목표는 많이 보내는 것과 안정적으로 보내는 것이다. 실제 Engineering에서는 회선 용량보다 보호절체와 생존성, 장애 시 어떤 단위로 어디까지 이중화되는지를 더 세밀하게 본다.

핵심 요약

전송망은 Working Path와 Protection Path를 미리 설계한다. 보호 대상은 Hardware, Path, Service로 나뉘고, SDH/MSPP·PTN·OTN/ROADM 계열마다 절체 방식이 다르다. 일반적으로 빠른 절체가 핵심이며, 카드·Shelf·회선·선로 중 어디까지 이중화했는지를 구분해서 봐야 한다.

1. 전송망 구조

구분주요 역할특징
지역 기간망지역 내 데이터 전송10G/100G 서비스와 수백 G급 집선
장거리 기간망지역 간 대용량 전송장거리 광 경로와 보호절체 중요
PTN 전국망B2B 전용회선 수용패킷 기반이지만 전송망 특성상 명시적 경로와 보호를 중시

2. 보호절체란?

보호절체는 장애가 발생했을 때 서비스를 계속 유지하기 위해 미리 준비한 예비 자원으로 전환하는 기술이다. 전송망에서는 IP Routing처럼 장애 이후 새로운 길을 탐색하는 것보다, 사전에 Working/Protection 구조를 설계해 두는 것이 중요하다.

보호 대상의미
Hardware ProtectionPower, Card, Unit, Shelf, 장비 자체를 이중화.
Path Protection주 경로 장애 시 예비 광/회선 경로로 전환.
Service Protection중요 고객 서비스 자체를 이중화해 회선/터널 장애에도 유지.

3. Standby와 이중화 방식

방식설명
Cold Standby예비 장비가 비활성 상태이며 장애 후 기동/전환.
Hot Standby예비 장비가 동작 가능한 상태로 즉시 대기.
Active-Standby주 장비가 서비스하고 예비 장비가 상태를 동기화하며 대기.
Active-Active양쪽이 실제 트래픽을 처리하며 부하를 나눔.

4. SDH / MSPP 계열 보호절체

SNCP

SNCP는 동일 신호를 Working Path와 Protection Path로 함께 보내고, 수신측이 더 정상적인 신호를 선택하는 방식이다. 회선 단위 보호에 가깝다.

Source
 ├─ Working Path ───┐
 └─ Protection Path ─┤→ Receiver selects healthy signal

BLSR

BLSR은 Ring 구조에서 장애가 난 구간을 피해 반대 방향으로 우회시키는 방식이다. 특정 회선보다 링/구간 단위 생존성 확보에 적합하다.

Linear Protection

두 지점 사이에 Working과 Protection을 두는 선형 구조다. 1+1 방식에서는 같은 신호를 두 경로로 항상 보내고 수신측에서 선택한다.

5. PTN 보호절체

LAG

여러 물리 포트를 하나의 논리적 링크처럼 묶는다. 하나의 포트가 장애 나도 전체 서비스가 바로 끊기지 않고 남은 대역폭으로 유지할 수 있다.

10G + 10G + 10G = 30G
1 port failure → available capacity 20G

Tunnel Protection

PTN은 패킷 기반이지만 전송 서비스이므로 Primary Tunnel과 Protection Tunnel을 미리 구성해 장애 시 전환한다. 여기서 Tunnel은 미리 설정된 가상의 전달 경로다.

PW Protection

Pseudowire 단위, 즉 고객 서비스 자체를 이중화하는 방식으로 이해하면 된다. 매우 중요한 회선에서는 하위 Tunnel뿐 아니라 서비스 레벨 보호가 필요하다.

6. ROADM / OTN 계열 보호절체

기술보호 단위관점
ROADM광 파장WSS 등을 통해 광 계층에서 파장 경로를 제어.
OTN회선/Container전기적 OTN 계층에서 서비스 회선 보호.
ASON동적 경로OTN에서 복수 경로를 활용해 생존성과 경로 유연성을 높임.

E-SNCP

경로는 이중화하지만 카드가 단일이면 카드 장애에는 취약하다. 즉 ‘Line 이중화’와 ‘System 이중화’는 같은 말이 아니다.

Y-Cable Protection

Y-Cable은 광신호를 두 갈래로 나누고 두 Transponder로 전달한다. 실제 절체 판단은 Transponder 쪽에서 한다. Client Port, Unit, Path까지 보호 범위를 넓힐 수 있지만 양쪽 송신 충돌을 막기 위한 제어가 필요하다.

OPS Protection

OPS(Optical Protection Switch)가 광신호 기준으로 Working/Protection을 선택한다. Shelf 자체를 분리할 수 있어 장비 장애까지 고려한 높은 생존성을 만들 수 있다.

7. Shelf / Slot / Unit / Transponder

용어의미
Shelf하나의 장비/시스템 단위.
Slot장비 안에서 카드를 장착하는 물리적 자리.
Unit / Card실제 기능을 수행하는 카드.
TransponderClient 신호를 Line-side 광신호로 변환하거나 반대로 복원.

운영에서는 단순히 ‘이중화 되어 있다’가 아니라, 어느 단위가 이중화되어 있는지 확인해야 한다. Power만 이중화되어 있어도 Card 장애에는 죽을 수 있고, Card까지 이중화되어 있어도 동일 Shelf 장애에는 취약할 수 있다.

8. 장애를 볼 때의 순서

1. 어떤 서비스가 영향을 받았는가?
2. 장애 단위가 Port / Card / Shelf / Node / Fiber 중 무엇인가?
3. Working → Protection 절체가 발생했는가?
4. 절체는 성공했는가, 용량은 충분한가?
5. Protection 경로가 동일 위험 구간을 공유하지 않는가?
6. 고객 서비스 자체(PW 등)도 이중화되어 있는가?

기간망 Engineering에서 중요한 것은 ‘장애가 나지 않는 망’이 아니라, 장애가 나도 서비스 영향이 최소화되도록 미리 실패 구조를 설계하는 것이라는 점이다.
