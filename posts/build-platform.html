컨테이너 빌드 1,319초를
330초로 줄이기

FastAPI에서 Kubernetes Pod를 생성하고 Kaniko가 이미지를 빌드해 Registry로 push하는 내부 ML 플랫폼의 Build 경로를 운영하며 병목을 추적했다.

−74.9%1319s → 330.6s

빌드도 하나의 제품 기능이다

사용자는 Build 버튼 하나를 누르지만 뒤에서는 API 요청, Queue, Kaniko Pod, cache storage, Registry, Kubernetes Watch와 상태 저장이 연결된다. 어느 한 부분의 실패도 사용자는 하나의 ‘빌드 실패’로 경험한다.

Cache만 켜면 끝나지 않았다

Kaniko cache 구조와 공유 storage 경로를 조정하고, 빌드 컨텍스트와 cache I/O가 실제로 어디를 통과하는지 확인했다. 동시에 요청이 몰릴 때는 Semaphore와 FIFO Queue로 실행 수를 제한해 플랫폼 전체가 흔들리지 않도록 했다.

운영 가능한 상태 모델

Pod가 OOMKilled 되거나 restart 되는 경우를 Kubernetes Watch로 추적하고 사용자에게 의미 있는 실패 상태를 반환하도록 했다. 성공 속도뿐 아니라 실패가 설명 가능한 시스템을 만드는 것이 플랫폼 운영의 핵심이었다.
