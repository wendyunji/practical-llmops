VOICE · TERMINAL PRACTICE

단말 접속 실습
VoIP / SSW / IP Phone

1. VoIP 기본 구조

VoIP는 음성을 IP Network 위에서 전달하는 방식이다. 일반 아날로그 전화기는 RJ11을 사용하지만 IP Phone은 Ethernet(RJ45)으로 네트워크에 직접 연결된다. 가정/사무실에서는 공유기가 공인 IP를 받고 내부 단말에 사설 IP를 할당하는 형태가 일반적이다.

핵심 분리

SIP는 통화 연결·수락·종료 등 Signaling을 담당하고, RTP는 실제 음성 Media를 전달한다.

2. 통화 연결 Flow

발신 단말
→ SIP INVITE
→ Softswitch / IP PBX
→ 100 Trying
→ 180 Ringing 또는 183 Session Progress
→ 200 OK
→ ACK
→ RTP 양방향 Media
→ BYE
→ 200 OK

단말 등록(Register) 단계에서는 계정 ID/PW 같은 인증 정보가 사용될 수 있고, 실제 Call Setup에서는 SDP 등을 통해 RTP를 주고받을 IP/Port가 협상된다. 등록과 통화 연결은 서로 다른 단계다.

3. SIP 응답 코드

메시지의미
100 Trying요청 처리 중.
180 Ringing상대방 벨이 울리는 중.
183 Session Progress연결 전 Media 진행. 안내음/컬러링 등 가능.
200 OK요청 성공. 상대방이 통화를 수락.
ACK200 OK 수신 확인.
BYE통화 종료 요청.

4. 단말과 운용 구조

전화 단말끼리 바로 연결되는 것이 아니라 단말, 공유기, Access Network, 사업자 Voice Network, Softswitch/IP PBX, Interworking 구간을 거친다. 기업 환경에서는 IP PBX가 내선/외선, 단말 등록과 통화 제어를 담당할 수 있다.

IP Phone
→ Router / Access Network
→ Voice Core / Softswitch
→ Interworking Network
→ 상대 단말 / Mobile / PSTN

5. MTA

MTA는 Ethernet 쪽과 RJ11 쪽을 연결하여 기존 아날로그 전화기를 IP 기반 전화 서비스에 붙일 수 있도록 한다. 즉 Analog Terminal과 IP Voice Network 사이의 Access Gateway 역할을 수행한다.

6. 단말 Provisioning

단말은 단순히 연결한다고 서비스가 바로 되는 것이 아니라 관리 시스템에서 필요한 정보를 갖고 있어야 한다.

  • MAC Address
  • IP Address
  • Firmware Version
  • 전화번호
  • Softswitch / Registrar 주소
  • 인증 ID / Password
  • 단말 상태

이 정보를 기반으로 단말은 서버 위치와 계정을 알고 Register를 수행한다. 중앙 관리 체계가 있어야 Firmware Upgrade, 장애 처리, 자산 관리, 원격 운영이 가능하다.

7. RTP와 품질

사람의 음성은 단말 내부 DSP에서 디지털 데이터로 처리되고 RTP Packet으로 전송된다. 짧은 주기로 계속 패킷이 흐르기 때문에 Packet Loss, Delay, Jitter에 민감하다.

문제사용자 영향
Packet Loss음성 일부가 사라져 끊기거나 깨짐.
Delay상대방 음성이 늦게 도착해 대화가 겹침.
JitterPacket 도착 간격이 불규칙해 음성이 흔들림.

교육 메모에서는 RTP가 초당 약 50개 수준의 Packet으로 흐르는 예시를 사용했다. Codec과 Packetization Interval에 따라 실제 수치는 달라질 수 있다.

8. 번호 체계와 위치

지역번호 기반 일반 전화와 070 Internet Phone은 번호와 물리 위치의 관계가 다르다. IP Phone은 인터넷만 연결되면 물리적으로 다른 위치에서도 동작할 수 있으므로 사업자 입장에서는 번호, 실제 위치, 긴급통화, 과금/정책을 연결하는 운용이 중요하다.

9. 보안과 Packet 분석

VoIP는 IP망 위에서 동작하기 때문에 Network Security의 영향을 직접 받는다. 인증/암호화/Firewall이 부실하면 감청이나 세션 악용 위험이 생길 수 있다. Wireshark에서는 SIP Signaling과 RTP Flow를 분석할 수 있고, 암호화되지 않은 RTP는 조건에 따라 음성 복원이 가능할 수 있으므로 운영 환경에서는 보안 설정이 중요하다.
